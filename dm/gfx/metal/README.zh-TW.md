# dm/gfx/metal — 最小 Metal 離屏示例

English: [README.md](README.md)

一個獨立的小模塊：用純 C 接口包住 Metal，把畫面渲到離屏紋理再讀回 CPU，不上屏。它不編進宿主（`dm/host/Makefile` 不收本目錄），遊戲實際用的 Metal 回放層在 `../nvn/nvn_mtl.m`。這裡留作一個能獨立編譯、幾十行就能看懂的參照，以及驗證 Metal 行為的小探針。

## 接口（`mtl_backend.h`）

| 接口 | 作用 |
|---|---|
| `mtlb_init()` / `mtlb_shutdown(ctx)` | 建 / 釋放上下文：設備、命令隊列、當前幀的命令緩衝、管線緩存 |
| `mtlb_target(ctx, w, h, fmt)` / `mtlb_target_free(rt)` | 建 / 釋放一個離屏渲染目標，格式為 `MTLB_FMT_BGRA8` 或 `MTLB_FMT_RGBA8` |
| `mtlb_clear(ctx, rt, r, g, b, a)` | 往當前幀錄一個渲染通道，把目標清成指定顏色 |
| `mtlb_triangle(ctx, rt)` | 往當前幀再錄一個渲染通道（保留已有內容），畫一個三色三角形 |
| `mtlb_readback(ctx, rt, buf, size)` | 提交當前幀、等 GPU 完成，把像素按行緊排讀回 `buf`（第 0 行是圖像頂部） |

函數返回 0 表示成功、-1 表示失敗，失敗原因打到標準錯誤。實現在 `mtl_backend.m`（Objective-C，ARC）。

設計要點：

- **一幀一個命令緩衝**：第一次錄通道時才創建，之後的清除、三角形都追加進同一個命令緩衝，讀回時才提交。
- **渲染目標不是全局變量**：上下文與每個目標都是不透明指針。
- **存儲模式用 Shared**：在統一內存設備上，Shared 紋理可以直接當渲染附件，GPU 完成後 CPU 直接讀，不需要中轉緩衝。非統一內存設備上 `mtlb_init` 直接報錯。
- 三角形的著色器是內聯的 MSL，運行時編譯。

## 編譯與運行

```sh
make -C dm/gfx/metal        # 產出 test_offscreen
make -C dm/gfx/metal run    # 跑自測，退出碼 0 表示全過
make -C dm/gfx/metal clean
```

只需要 Xcode 的命令行工具，不需要遊戲文件。編譯產物已列入本目錄的 `.gitignore`。

## 自測（`test_offscreen.c`）

期望值全部在測試裡獨立算出，不讀後端內部數據：

- 三角形頂點在測試裡另抄一份；
- 歸一化坐標換算到像素：`px = (x + 1) / 2 · W`，`py = (1 − y) / 2 · H`；
- 像素中心的顏色按重心坐標對三個頂點顏色線性插值。

兩個測試對 BGRA8、RGBA8 兩種格式各跑一遍：

1. 清成純色，逐像素比。
2. 清屏後畫三角形：三角形內側（離邊超過 1 像素）的像素與插值值比，容差見源碼裡的 `TOL`；外側像素與清屏色比；緊貼邊的 1 像素帶跳過，光柵化的邊緣規則不在本測試範圍內。

讀回前先把緩衝填成 0x5a，防止「後端什麼都沒寫也判過」。

## 探針（`probe/p_nocopy.m`）

單文件程序，沒有構建目標，需要時手動用 clang 編譯。它驗證回放層內存池做法所依賴的一件事：在一段不按頁對齊的內存上，把首尾外擴到頁邊界後可以建成零拷貝的 `MTLBuffer`，兩個這樣的緩衝允許重疊，GPU 寫入的內容 CPU 經原指針能讀到。

## 局限

- 三角形頂點寫死在 `mtl_backend.m`，沒有頂點緩衝、著色器、視口等可配置狀態。
- `mtlb_readback` 同步等整幀完成，會阻塞調用線程。
- 只支持單個顏色附件、兩種 8 位格式；沒有深度 / 模板、多重採樣、多附件。
- 非線程安全；只支持統一內存設備。
